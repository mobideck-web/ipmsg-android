# Contributing

Keep the product simple: local operation, four main tabs, Windows IP Messenger compatibility, explicit sharing approval, predictable storage and clear recovery. Discuss accounts, cloud services or broad remote-control scope before proposing them.

1. Check issues and describe a concrete trigger/expected result for behavioral changes.
2. Fork and create a focused branch. Follow Kotlin/Compose patterns and retain Android 10+ support.
3. Preserve protocol compatibility, fingerprint trust, permissions and third-party notices.
4. Include meaningful validation appropriate to the change. State checks not run; historical reports/obsolete tests are not current acceptance evidence.
5. Use synthetic data in screenshots. Never commit personal messages/media, keys, camera tokens, local.properties or build output.

Use SECURITY.md for vulnerabilities. Contributions retain attribution and are supplied under the applicable project licensing terms. No separate contributor agreement is introduced.
